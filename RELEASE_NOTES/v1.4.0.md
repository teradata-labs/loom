## Summary

v1.4.0 is a feature release focused on **context precision and human-in-the-loop control**. The context machinery is rewritten around compile-per-call compilation (every rendering decision made at the moment of the LLM call), skills and patterns move from per-turn push to on-demand pull, and two HITL layers land: declarative approval gates for workflows with durable checkpoint/resume, and a fail-closed tool-admission chain that can hold a turn for a human verdict. It also ships backend-agnostic OTLP trace export, multimodal user turns, a replay/import arrival-time override, and a set of Bedrock, workflow-loading, security, and packaging fixes — including repair of Homebrew tap publishing that had been silently broken since v1.0.1.

This release contains **breaking changes** — see the next section before upgrading.

- **102 commits** since v1.3.0 (16 features, 39 fixes, dependency/CI maintenance)
- **4,005 test functions** across 476 test files (up from 3,739/393), 0 race conditions
- **10 new database migrations** (`000014`–`000023`); applied automatically on first start

## Breaking Changes

| Change | Impact | Action |
|--------|--------|--------|
| **Skills/patterns push removed** (#278) | Per-turn skill discovery-and-activation push and the pattern injection channel are gone; `record_finding` tool and the findings channel removed | Skills load via the `manage_skills` builtin (`list`/`load`); patterns via `load_pattern` |
| **Compaction trigger** (#278) | `maxL1Tokens` no longer triggers compaction; compaction is budget-based | Remove reliance on the fixed trigger; the field remains validated config |
| **Context compile-per-call** (#288) | Tool results over one 16 KiB threshold (16384 bytes) render as offload stubs; results render as verbatim string or JSON, never Go map syntax; advertised tools and error/SQL-result/shared-memory stores are per-session | Review anything that parsed the previous rendering; use `query_tool_result`/`get_tool_result` doors for offloaded results |
| **User-turn timestamp prefix removed** (#306) | Stored user `Content` no longer starts with `[Mon 2006-01-02 15:04 MST] `; clients see the words verbatim | Remove any client-side prefix parsing; arrival time is on the `Timestamp` field |
| **`DeleteSession` semantics** (#146) | Returns success for a store-only session (previously `NotFound`) | Update clients keying off the `NotFound` code |
| **Go 1.26 toolchain** (#271) | Required for source builds | Upgrade Go |
| **Auto-applied DB migrations** | `000014`–`000023` apply on first start (analytics views, RLS infrastructure, tool-outcome policy/admission columns, context compilation, human-request store) | Back up databases before upgrading |

### Migration Notes

- **Skills:** the pull model renders bound skills' names and descriptions once into the system prompt at session creation; the skill body arrives only when the model loads it. If an agent depended on skills being injected every turn, bind them and expect the model to `load` on demand.
- **Offloaded tool results:** results over 16 KiB render as stubs with a `query_tool_result` door (when the row is durable). An offload-exempt tool set is configurable via `SetOffloadExemptTools` (#297); no tools are exempt by default.
- **Timestamps:** per-turn temporal grounding now renders from the durable `Timestamp` into the compiled LLM view only. Graph-memory extraction anchors on the newest turn's `Timestamp` (falling back to content-embedded dates, then wall clock). Replayed/imported histories should pass `WeaveRequest.occurred_at` (see Added Features) so anchoring reflects the conversation's real time.
- **Databases auto-migrate** (`000014`–`000023`) on first start of the upgraded server; back up first.

## Added Features

### Context Compilation (#288, #297)
Compile-per-call context: arrival appends messages in full and persists each row once; a single compilation algorithm decides at every LLM call what renders full, what renders as an offload/eviction stub, and when conversation folds into the summary. Large-result offload is a pure render condition of compilation at one 16 KiB threshold, with a configurable exempt tool set (none exempt by default). Proactive relief replaces multiple ad-hoc thresholds.

### Human-in-the-Loop: Approval Gates & Tool Admission (#269, #300)
Two layers, one mechanism. `PipelineStage.hitl_gate` (proto) fires deterministically after a stage's output validates and before the next stage runs, with durable checkpoint/resume — no LLM decides whether to ask. Beneath it, a tool-admission hook library: config-built bindings (`gated-allowlist` / `denylist` / `audit` / `ask`) with dot-path matchers over call params are evaluated against every tool call before execution (unmatched calls pass through); the most restrictive verdict wins; a config that fails to compile aborts serve startup rather than running ungoverned (fail-closed). `ask` verdicts hold the turn on a human-request store (SQLite + PostgreSQL) with expiry, and admission decisions are audited on tool outcomes.

### Context & Skill Management (#278)
`manage_skills` builtin (`list`/`load`): a load activates the skill for the session, registers its required tools so the same turn can use them, and delivers the skill body into the conversation. Budget-based compaction uses the LLM compressor when a prompt registry is configured (preserving decisions and approvals with their scope, open commitments, and reload pointers); the heuristic summarizer remains the fallback.

### OTLP Tracing (#255)
`OTelTracer` exports spans to any OTLP/HTTP backend (Opik, Jaeger, Tempo). Loom span attributes translate to OTel `gen_ai.*` semantic conventions; `mode: otel` in the observability config, plus auto-selection from `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` / `_HEADERS` env vars. Credential and PII redaction is default-on for exported spans. ⚠️ OTLP/HTTP only — OTLP/gRPC is not implemented.

### Multimodal User Turns (#249)
`ChatWithContentBlocks`: user turns carry text + image content blocks end-to-end from the agent API to providers, with the canonical text preserved on the stored turn.

### Replay/Import Arrival Time (#308)
`WeaveRequest.occurred_at`: replayed or imported conversations anchor every row persisted during the call (user turn, assistant reply, tool rows) at their historical time, keeping temporal grounding consistent with when the conversation actually happened. Rejected with `FAILED_PRECONDITION` unless the operator sets `server.allow_time_override: true` (default off); future-dated values rejected with `INVALID_ARGUMENT`.

### Session Artifact Metadata & ListSessions API (#146)
Opt-in session `metadata.json` (default **off**) colocating `agent_name`, `ended_at`, `metadata_status`, `artifact_count`, and allowlisted attribution context next to a session's artifacts. `ListSessions` gains opt-in pagination (`limit`/`offset`; default page size 50, max 500) and `metadata_status`/`project_id` filters.

### Other
- OpenAI client: `ExtraHeaders` config forwarded on requests (#265)
- Release pipeline publishes the homepage (`web/` → gh-pages) with a version-stamp check (#275)

## Bug Fixes

- **Temporal grounding leak (#306)** — timestamps no longer leak into user-visible message bodies; per-turn grounding renders from `Timestamp` into the compiled view only
- **Bedrock (#301, #302)** — SDK tool mappings isolated per request (concurrent sessions no longer corrupt each other's tool maps); canonical provider identity
- **Workflow loading (#298, #307, #310)** — parallel workflow tasks load from the canonical schema; canonical fork-join and all canonical pattern types load in the registry
- **TUI (#240, #241)** — no hardcoded default model shown at startup; readline keys (ctrl+a/e/k/u/w) freed in the chat input
- **Quickstart (#239)** — Bedrock API-key auth and a non-exhaustive model picker
- **CI (#242)** — unit-test de-flake: SSE happy path, live web-search calls removed from unit runs
- **Packaging (#272, #274)** — Homebrew tap publishing repaired (silently broken since v1.0.1: `release: published` triggers never fire for GITHUB_TOKEN-published releases; publishers are now dispatched explicitly); repo templates under `packaging/macos/homebrew/` are the single source of truth for tap formulas

## Known Limitations

- **OTLP export is HTTP-only** — `OTelTracer` speaks OTLP/HTTP; gRPC-only collectors need an HTTP/gRPC gateway.
- **Skill risk levels** — recorded and block when `require_approval=true`; the interactive approval flow for skills is separate from the tool-admission `ask` mechanism.
- **TaskService gRPC surface** — unchanged from v1.3.0: 11 of 19 RPCs served.
- **Vector recall** — unchanged from v1.3.0: SQLite brute-force; PostgreSQL pgvector path stubbed.
- **Graph memory event dates over gRPC** — unchanged from v1.3.0: internal Go layer only.

## Manual Steps Required

### Step 1: Verify the prepared release locally

```bash
cd ~/Projects/loom
just version-verify          # all 15 files should report v1.4.0
git show HEAD                # review the "Bump version to v1.4.0" commit

```

### Step 2: Push the release

> The push is the point of no return — it triggers the public GitHub Release workflow and package-manager publishing.

```bash
git push origin main
git push origin v1.4.0
```

This triggers:
- `.github/workflows/release.yml` — builds 12 binaries (loom / looms / loom-standalone × linux-amd64 / darwin-amd64 / darwin-arm64 / windows-amd64), GPG-signs checksums, builds the combined Windows package, generates SLSA provenance attestations, and publishes the homepage to gh-pages
- `publish-homebrew.yml`, `chocolatey-build.yml`, `publish-winget.yml` — dispatched by the `publish-packages` job (not by `release: published`, which GITHUB_TOKEN suppresses)

The workflow's first job re-verifies that the tag matches the `VERSION` file and that all version files are consistent; a mismatch fails the release.

### Step 3: Monitor GitHub Actions

Watch <https://github.com/teradata-labs/loom/actions> for:
- ✅ `release.yml` completes; all 12 binaries + checksums + signatures uploaded
- ✅ Combined Windows package uploaded
- ✅ SLSA provenance attestations created
- ✅ Homepage published to gh-pages (version stamp verified)
- ✅ Homebrew / Chocolatey / winget jobs complete (Homebrew tap merge depends on the `HOMEBREW_TAP_TOKEN` PAT and the tap ruleset's admin bypass — recovery commands in `docs/reference/release-packaging.md`)

## Verification

After the release completes:

```bash
# 1. Download a binary + checksum + signature
wget https://github.com/teradata-labs/loom/releases/download/v1.4.0/loom-linux-amd64.tar.gz
wget https://github.com/teradata-labs/loom/releases/download/v1.4.0/loom-linux-amd64.tar.gz.sha256
wget https://github.com/teradata-labs/loom/releases/download/v1.4.0/loom-linux-amd64.tar.gz.sha256.asc

# 2. Import the public key and verify the signature
curl -sL https://raw.githubusercontent.com/teradata-labs/loom/main/loom-release-key.asc | gpg --import
gpg --verify loom-linux-amd64.tar.gz.sha256.asc   # Good signature from "Loom Release Bot"

# 3. Verify the checksum
sha256sum -c loom-linux-amd64.tar.gz.sha256       # loom-linux-amd64.tar.gz: OK

# 4. Verify SLSA provenance
gh attestation verify loom-linux-amd64.tar.gz --owner teradata-labs

# 5. Verify the binary reports the right version
tar xzf loom-linux-amd64.tar.gz && ./loom-linux-amd64 --version   # v1.4.0
```

## Rollback

If something is wrong after tagging but before pushing:

```bash
git tag -d v1.4.0                      # delete the local tag
git reset --hard HEAD~1                # drop the bump commit (verify count first)
```

If the tag was already pushed, do **not** delete or move it — published package versions cannot be overwritten. Cut a new patch release (v1.4.1) with the fix instead.
